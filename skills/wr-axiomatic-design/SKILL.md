# wr-axiomatic-design 提取功能需求做下三角解耦

多代理多路并行开发时，就算每条支线独占不同的文件白名单，如果架构本身存在反向依赖，合到一起照样互相打架、改一处坏一片。动手拆活之前，先用 MIT 工程学者 Nam Pyo Suh 在公理设计（Axiomatic Design）里提出的两条公理算一遍矩阵，把耦合在纸面上消灭掉。

## 两条核心公理

1. **第一公理（独立公理）**。保持各个功能需求彼此独立。理想的设计里，调整一个设计参数只会影响它对应的那一条功能需求，或者按固定顺序逐层生效而不反过来破坏前面已经定下的功能。
2. **第二公理（信息公理）**。在同样满足第一公理的多个方案里，选择信息含量最小、实现成功率最高、最不需要额外特判与人工记账的方案（零件更少、状态分支更少、依赖链更短）。

## 第一步 提取独立的功能需求 FR 与设计参数 DP

动笔写代码或派活之前，先列清两张一一对应的清单。

1. **功能需求清单（FR1, FR2, ..., FRn）**。站在系统对外承诺或用户要的结果视角，写出彼此独立、互不重叠的最小目标列表。每条用「动词 + 宾语」写清要做到什么，不混入具体技术实现细节。
2. **设计参数清单（DP1, DP2, ..., DPn）**。针对每一条 FR，找出唯一主导它的工程实现载体、数据文件、核心模块或独立接口。尽量保持一条 FR 对应一个主导 DP。
3. **拆干净自检**。如果两条 FR 其实在说同一件事，先合并；如果某个 DP 同时被多条互不相干的 FR 反复拉扯，说明这个 DP 混进了两套职责，先拆开再画矩阵。

## 第二步 画出 FR × DP 设计矩阵并判别三种耦合

按 `[FR] = [A] × [DP]` 列出矩阵，行代表各条功能需求 FR，列代表各个设计参数 DP。如果修改第 j 列的设计参数 DPj 会影响第 i 行的功能需求 FRi，就在该格填 `X`；完全不影响就填 `0`。

根据非零项 `X` 的分布位置，矩阵分成三类。

| 矩阵形态 | 结构特征 | 能否直接多路并行 |
| --- | --- | --- |
| 无耦合（对角阵） | 只有主对角线是 `X`，左下角和右上角全是 `0` | 可以任意顺序修改，也可以全部同时多路并行 |
| 准耦合（下三角阵） | 主对角线与左下角允许有 `X`，右上角全部是 `0` | 存在单向顺序依赖，先锁定靠前的基础 DP 后，下游各路即可并行推进 |
| 强耦合（上三角出现 `X`） | 主对角线右上方出现至少一个 `X`，形成环向或反向依赖 | 严禁直接多路并行，必须先消掉右上角反向耦合 |

示例对比如下。

```text
1. 无耦合（对角阵，最理想）
   FR1   [ X  0  0 ]   DP1
   FR2 = [ 0  X  0 ] × DP2
   FR3   [ 0  0  X ]   DP3

2. 准耦合（下三角阵，可按顺序锁定后并发）
   FR1   [ X  0  0 ]   DP1（先定稿）
   FR2 = [ X  X  0 ] × DP2（只读 DP1）
   FR3   [ 0  X  X ]   DP3（只读 DP2）

3. 强耦合（右上角有 X，改 DP2 会破坏 FR1，禁止并发）
   FR1   [ X  X  0 ]   DP1
   FR2 = [ X  X  X ] × DP2
   FR3   [ 0  X  X ]   DP3
```

## 第三步 两招消掉右上角反向耦合

只要右上角还存在 `X`，就不允许开多代理并发干活。按下面两招把矩阵逼回下三角阵或对角阵。

1. **第一招，重排执行与定稿顺序**。检查是不是单纯把依赖顺序写反了（原本下游模块写在了上游前面）。尝试同步调换对应的 FR 行与 DP 列顺序，看能否把右上角的 `X` 全部翻到左下角，直接收敛成下三角阵。
2. **第二招，抽取唯一真源（Single Source of Truth）斩断回边**。如果调换顺序后右上角依然存在 `X`，说明两个模块都在各自维护一份会互相影响的事实、常量或状态。把共同依赖的那份事实抽出来，独立成上游唯一的公共真源 DP0（例如共享契约 `docs/SPEC.md`、纯数据表、根级样式变量或互斥状态机），让原本互相拉扯的两个模块同时改成只读 DP0 的下游分支。双向依赖立刻断成两条单向依赖，右上角归零。
3. **再用第二公理挑最简方案**。如果抽出唯一真源后有多种都能满足下三角阵的写法，选状态组合最少、不需要人工记忆同步、靠静态类型或脚本就能一次验完的那一版。

## 第四步 验明下三角阵再放行多路并行

向协调人或执行帮手发派活任务书前，必须核对下面四条出口条件。

1. FR 与 DP 一一对应，没有职责混杂的超级模块。
2. `FR × DP` 设计矩阵右上角全部为 `0`，确认属于无耦合对角阵或准耦合下三角阵。
3. 下三角阵里处于上游的基础真源（如 DP0、DP1）必须先由主脑定稿并锁定为只读，再启动下游各棵 `git worktree` 并行实现。
4. 把最终矩阵与定稿先后顺序写入 `docs/SPEC.md` 或派活任务书的参考准数栏，再结合 `wr-split-work` 多工作区并行执行。
