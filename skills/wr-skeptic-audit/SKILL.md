# wr-skeptic-audit 三席物理隔离验货

写代码的会话里装满了一路妥协的理由，自己审自己几乎永远说「没问题」。把验收切给三个彼此隔离的全新会话，各看各的输入，各挑各的刺。

## 触发节奏与总原则

1. **大波合齐后集中审一次。** 等一整批功能全部合入集成分支后统一过三席，不搞每改十行来回拉扯审核。
2. **物理隔离，严禁串台。** 三个席位必须是三个全新会话，互相不共享对话记录，更严禁喂入写代码过程的任何辩解、聊天解释或「为什么要这样写」的说明。
3. **默认不通过，凭证据放行。** 任何放行结论必须附真实截图坐标、原句摘录或 `file:line`，没有证据不许判过。
4. **三席全部只读。** 审查席位绝不直接改代码、不提交、不重启服务；问题一次汇总成清单，交回执行方一轮修清。

## 第一席 极懒初中生审交互（严禁读源码）

- **喂入材料**仅限真机或无头浏览器实拍截图（宽屏、窄屏、浅色、深色、空态与满载态）、操作录屏或界面状态序列、完成主任务的点击步数记录。**严禁提供任何代码文件、CSS、架构文档或开发者解释。**
- **审查身份**是一个完全不懂技术、绝不看说明书、多点两下就嫌烦的普通新手。
- **必查 6 项**见下面清单。
  1. 第一眼 5 秒内能不能看懂这页干什么用、第一步该点哪里？
  2. 完成最核心的一件事要点几步？哪一步多余或绕路？
  3. 有没有文字被截半个字、按钮压在一起、阴影或浮层盖住字、深浅色看不清？
  4. 报错或空状态说不说人话？下一步该干嘛明不明白？
  5. 点错以后能不能一眼找到退回或撤销？
  6. 手机窄屏下有没有横向拖出白边或点不到的死按钮？
- **输出格式**逐条写「截图编号与位置 + 哪里卡住/嫌烦 + 期望怎么顺手」，只挑毛病不夸奖。

## 第二席 初中生审文案与模型味（严禁读源码）

- **喂入材料**仅限从界面、菜单、弹窗、报错提示、帮助页和说明文档里导出的纯文本清单。**严禁提供任何代码文件和实现逻辑。**
- **审查身份**是平时只看大白话的普通读者，对术语、套话和翻译腔极其敏感。
- **必查 5 项**见下面清单。
  1. 有没有普通人读不懂的技术缩写、英文代码、内部代号或生造概念？
  2. 同一个功能在不同页面是不是换了两种叫法（前后打架）？
  3. 有没有浓重模型味，比如破折号满天飞、先否定再翻过来的套路句、行业黑话、硬凑三连排比、结尾虚空拔高？
  4. 有没有替用户编造心理活动或拍胸脯夸大（例如没核实过的「极致」「秒级」「十万好评」）？
  5. 按钮文案、标题和提示语能不能砍掉一半废话变得更直白？
- **输出格式**逐条列「原句位置 + 原句摘录 + 毛病类型 + 一句更平实的改法」。

## 第三席 老兵工程师只读总审（全新只读会话）

- **喂入材料**只给下面四样东西，严禁喂入作者聊天记录。
  1. 用户的原始需求原话；
  2. 唯一规格准数文件 `docs/SPEC.md`；
  3. 集成头相对基线的完整 `git diff`（大改动先看 `--stat` 再按模块分片读）；
  4. 实现方宣称的检查结果与验收单。
- **必查 8 项证据清单**（每项给出 `PASS / WARN / FAIL` 并附 `file:line`，无行号视为未核查）。
  1. **范围与合并安全**，查有没有改到白名单外的文件，合并冲突时有没有悄悄冲掉别人的逻辑。
  2. **契约与权限一致**，查 `docs/SPEC.md` 里的枚举值、字段名、权限表、边界限制与代码逐字对得上吗。
  3. **全仓零死调用**，查改名、换签名或删除的函数、路由、样式类在全仓还有没有遗漏的旧调用。
  4. **测试真伪推演**，对照改动文件查核心分支真有行为测试覆盖吗，有没有源码搜词、吞异常、跑 0 条用例的水测试。
  5. **静态语法与类型**，查语法、类型、Lint、导入路径是否全部干净无报错。
  6. **运行链隐患**，按真实执行顺序顺一遍，查有没有漏写异步 `await`、空 `catch` 吞错误、未清理定时器/监听器、竞态覆盖。
  7. **文档与配置同步**，查对外 README、示例配置、数据计数、版本号是否随改动同步更新。
  8. **残留与安全清理**，查有没有临时调试日志、硬编码本机路径、密钥字面量、未删干净的探针改动或垃圾文件。

## 汇总裁决

三席全部交卷后，把问题合并成一张分档清单交回执行方。
- **阻断项（必须修完复核）**，包括逻辑缺陷、合并误冲、交互死路、截字遮挡、隐私泄露、严重歧义文案。
- **建议项（本轮顺手清）**，包括多余点击步骤、拗口措辞、轻微样式瑕疵。
- **不改项（记录原因）**，明确属于下阶段需求范围的条目。
