# wr-plain-cn 平实中文写作与去机器味

写成一个真动手踩过坑、愿意把来龙去脉讲清楚的人在当面说话。不端架子，不表演深刻，不替当事人编心理戏。

---

## 第 0 步 首次对齐（每次启用本技能先做）

本技能是写作类技能，只用到下面第 5 题（回复语言），另外会追问一句「要不要在这个项目里启用平实中文文风检查（默认关闭，启用后只报告不拦截）」，答案写进 `wr.config.json` 的 `language.output` 和 `style.enabled`（`false` / `true`，默认 `false`），不标 `onboarded`，其余工程类问题留给工程技能去问。需要落款时，把用户自定义的落款文字写进 `style.signature`（留空则写完直接收笔）。

## 核心写作七条

1. **真实小事起手，不端架子**。从自己真做过的一件具体事情开头，讲清楚当初想做什么、第一版做出来看着像样、真上手用以后怎么接连出问题。绝不用宏大行业宣言、概念科普或卖点广告框开篇。
2. **连贯口语长句呼吸感**。一句话可以一口气顺下 15 到 40 多个字，把因果、转折、现场画面和举例子自然串下来，说到关键处再用利落短句收住。自然保留「然后」「后来我才慢慢想明白」「其实」「所以现在」这类真实口头连接词。彻底废除三五字一逗的电报碎句与一行一句装深沉，改稿时严禁越改越短。
3. **按做事先后自然推进，不套阶段模板**。顺着开工前、进行中、排错验货、最后打磨界面的真实先后展开，一小节讲透一个坑和一个解决办法。小节标题直接用大白话点出坑和办法，不硬编第一到第四阶段，不在每段末尾贴「第 X 个重要教训」，不硬凑形式化的箭头链和对照表。
4. **讲透因果给实招，只举通用例子**。每条做法顺着「踩过什么坑、为什么会这样、现在具体怎么干」写扎实，让读者照着就能用。举例只选人人都碰得到的通用场景（例如列表全量拉取卡死、删掉确认框导致误删），不塞自家产品版本号、体积字节数、测试条数或冷门私货。参考文章只用来体会语气，绝不抄它的原话、句式和结构。
5. **直白推荐与平实附链（同链只放一回）**。最值得照抄的核心做法直接挑明推荐，并把细节写全。提到参考资料或开源仓库时，全文同一个链接只放一回（放在文末收口处或最自然的一处供需要的人自取），不在开头、中间和结尾反复贴，也不用带货推销腔。
6. **零模型味底线、三条句法检查与写实收尾**。
   - **四条硬封底线**：全文严禁破折号；严禁先否定半句再翻过来的套路翻案句；严禁说教提示冒号（例如「核心在于」「说白了」后接冒号把一句简单的话切两半）；严禁 AI 强装口语的塑料假俚语和空洞商业黑话。
   - **三条句法检查**：
     1. **顿号连串**：一个分句里用顿号连着并列三项以上（表格和刻意列全的检查清单除外），拆成逗号或拆开来说。
     2. **分号拆句**：正文里用分号把句子接起来的，改成句号（表格除外）。
     3. **相邻句同构**：相邻三句套同一个句式骨架（例如连续三句「第一道……第二道……第三道……」），打散其中一句。
   - **事实与收尾边界**：绝不脑补未经证实的心理戏，未知就是未知，不吹没核实过的数字。事情讲完立刻收笔，回归克制（小项目不必大动干戈，做大了碰上哪个坑再回来对照看）。若用户在 `wr.config.json` 的 `style.signature` 里配了自定义落款，文末附上该落款；未配置就直接收笔。
7. **执行把关**。长文与深度叙事优先交由当前可用的主力写作模型按本规范主笔。写完后逐条核对引用的书目、规则原文与全部链接无误，再用本技能附带的文风检查脚本跑一遍清零问题。

## 交稿前自查清单

交稿前按下面四组过一遍，命中即改平实。

### A. 标点与句法检查
- 全文不出现破折号，停顿或补充改用逗号、句号或括号。
- 不出现先否定甲再转折肯定乙的翻案套路句。
- 不用说教提示冒号把普通陈述句切两半。
- 同一分句内不用顿号连着并列三项以上（表格和刻意列全的检查清单除外）。
- 正文不用分号接句子，一律改成句号（表格除外）。
- 相邻三句不套同一个句式骨架，发现三连同构打散其中一句。
- 不用「综上所述」「总而言之」「值得注意的是」「显而易见」当过渡拐杖。

### B. 词汇与语气检查
- 清除大厂黑话、公关套话与 AI 塑料假俚语，换成普通人日常动词。
- 不用「极致」「彻底」「革命性」「颠覆」等夸大修饰语。
- 不把简单动词名词化（如把「改了一版」写成「完成了迭代优化」）。
- 不出现每段开头硬贴加粗标签、说教主持人口吻或三五字一逗的电报碎句。

### C. 事实与细节检查
- 关键经历有真实可核实的动作、界面元素、报错原文或带样本边界的数字。
- 零脑补心理戏，原材料没写明的细节直写未知，不擅自补全。
- 抽象分类后面用括号补上具体日常场景，举例选人人都懂的通用场景。
- 不塞冷门产品版本号、字节体积或显摆式测试条数。

### D. 结构与收尾检查
- 开头直接从真实小事切入，不先扯宏观时代背景。
- 按做事先后顺序推进，不硬套阶段编号或教训模板。
- 同一个外部链接全文只放一回。
- 事情讲完直接停笔，不拔高到行业未来或鸡汤金句，按 `style.signature` 决定是否附落款。

## 可选的文风检查脚本

本技能附带一个零依赖 Node.js 检查脚本 `scripts/style-check.mjs`，检查破折号、翻案句、说教冒号、塑料假俚语、顿号连串、分号拆句和相邻句同构七类问题。

- **默认关闭，不打扰日常开发**：只有用户在首次对齐里选择启用（`wr.config.json` 中 `"style": { "enabled": true }`）时，脚本作为钩子或项目扫描才生效。
- **启用后默认只报告不拦截**：退出码保持 `0`，方便写稿时自己对照修改。需要硬拦截时，可在配置里把 `style.mode` 改成 `"enforce"` 或在命令行加 `--enforce`。
- **手动单文件体检**：不管配置里有没有开启，命令行直接传文件路径就能扫一份草稿：

```bash
node skills/wr-plain-cn/scripts/style-check.mjs path/to/draft.md
```

## 交付与返稿学习

- **默认交付**：按全部规则输出平实标准稿。
- **按需对照**：用户要求看不同传播角度时，可在标准稿下方附一篇不受规则约束的对照稿，并注明改动思路供取舍。
- **返稿学习**：用户发回修改稿时，对比被删掉的句子、换掉的词和断句节奏，把新的偏好沉淀到项目本地写作偏好文件中，越写越贴合作者自己的说话方式。
