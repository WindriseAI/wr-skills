# wr-ux-craft 界面省心规矩与跟手动效设计

软件里的复杂事情总量不会凭空消失，程序不扛，就轮到用户扛。本 Skill 把界面好不好用拆成可逐条核查的硬标准。

## 第 0 步 首次对齐（每次启用本技能先做）

<!-- wr-onboarding:start -->
先找配置文件 `wr.config.json`：从当前目录逐级往上找，再看用户目录（`~/wr.config.json`）；两份都有时，项目里的字段覆盖用户目录的。

- 读到 `"onboarded": true`，就按里面的字段办事，不再提问，直接往下走。配置里没写的字段按下面各题的默认值理解。
- 没有这个文件，或者没有 `"onboarded": true`，先把下面 8 题一次发给用户，每题括号里是默认值，并说明「回『好』就全按默认」。用户回「好」或只改了其中几题，其余一律按默认。
- 收到答复后，把答案连同 `"onboarded": true` 写进项目根目录的 `wr.config.json`（用户要求全局生效就写 `~/wr.config.json`），已有字段保留不动，写完告诉用户写在哪、怎么改。字段全集和说明见 github.com/WindriseAI/wr-skills 的 `examples/README.md`。
- 用户说「这次先不对齐」，就按默认值办事，不写文件，下次启用时再问。
- 钩子在 `onboarded` 变成 `true` 之前，除了碰凭据和递归强删照样直接拦，其余规则只记录不拦截。

1. 机器与测试环境：只有这一台电脑，还是另有测试机、容器或 CI？跑测试时能不能占用这台电脑的键盘、鼠标和浏览器？（只有一台；耗时长的测试先说预计多久，同意后在本机跑；可以占用）写入 `environment.machine`（`single` / `has-runner`）、`environment.heavyTestsOnMainMachine`（`allow` / `ask` / `deny`）、`environment.quietMainMachine`（`false`）、`environment.remoteHost`（测试机的 ssh 主机名，没有就留空）。
2. 系统与工具：用什么系统和终端？在哪个 AI 工具里用？有没有装 Orca 多代理工作台？（系统、终端和宿主自动探测；Orca 自动探测）写入 `environment.os`、`environment.shell`、`environment.host`、`tools.orca`。
3. 模型与额度：手上有哪几档模型？有没有第二家厂商的模型可以交叉复核？额度紧、一般还是宽松？（只用当前这一个模型；没有第二家；一般）写入 `modelTiers` 四档（全部留空就是单模型模式）、`review.crossVendor`（`false`）、`budget.mode`（`tight` / `normal` / `generous`）。
4. 协作与发布：一个人做还是团队？要不要让 AI 开多个帮手并行？默认分支叫什么？推送、发版和对外提交由谁确认？（一个人；要并行时先问；分支自动探测；推送和发版必须用户确认）写入 `workflow.team`（`solo` / `team`）、`workflow.parallel`（`off` / `ask` / `on`）、`workflow.defaultBranch`、`workflow.branchPrefix`、`workflow.publishConfirm`（`always` / `push-and-release` / `never`）。
5. 回复语言：回复用什么语言？（跟随用户提问的语言）写入 `language.output`（`auto` / `zh-CN` / `en`）。
6. 做事强度：新功能要不要先问清并写规格？动手前搜不搜现成开源方案，搜几个？要不要定十倍目标？（大活才先问并写 `docs/SPEC.md`；搜 5 个；十倍目标只在用户提到性能或体积时提议）写入 `rigor.askFirst`（`off` / `big-only` / `always`）、`rigor.specPath`、`rigor.openSourceSurveyCount`、`rigor.tenX`（`off` / `ask`）。
7. 安全尺度：安全红线用哪一档？有没有额外不许读的目录？（标准档：碰凭据和递归强删直接拦，git 硬重置只提醒；没有额外目录；删除走回收站）写入 `hookMode`（`observe` 起步）、`safetyGuard.profile`（`relaxed` / `standard` / `strict`）、`safetyGuard.extraProtectedPatterns`、`safetyGuard.trashCommand`。
8. 项目类型：这个项目是网页或桌面界面、命令行或库、后端服务，还是官网营销站？有没有线上用户？官网是否允许 AI 训练爬虫？（自动探测类型；没有线上用户；允许搜索爬虫，训练爬虫由用户定）写入 `project.kind`（`web-ui` / `cli-lib` / `backend` / `marketing-site` / `other`）、`project.hasOnlineUsers`、`geo.languages`、`geo.region`、`geo.crawlerPolicy`（`allow-all` / `block-training` / `custom`）。

本技能主要用到第 6 题（`rigor.impactCheck` 决定是否做二三阶影响检查）和第 8 题（`project.kind` 不是界面类时本技能不适用）。

## 第一步 开工前先锁死样式底表去掉模板味

动界面前先问一句：项目有没有设计规范或现成的设计令牌（Tailwind 主题、组件库主题、CSS 变量文件、设计稿里的样式表）。

- **已经有的**，直接沿用，把缺的几项补进同一处，不另起一份重复的变量表。
- **还没有的**，把颜色、字号、间距、圆角、阴影、动效时长写进一份根级样式变量文件，所有页面统一引用。

下面五条是默认建议，项目设计规范另有规定时以规范为准；后台、仪表盘、游戏这类界面按各自惯例取舍，但第 4 条在任何项目里都不能破。

1. 少用千篇一律的模板化装饰（例如大面积紫蓝渐变、廉价发光玻璃背景）。
2. 功能图标用统一线宽的矢量图标，不拿表情符号充当。
3. 减少无意义的边框和卡片套卡片的嵌套层级。
4. 不用虚构的用户数、评分或客户好评充数，没有真实数据就空着。
5. 落地页和工具首页在桌面常见视口（如 `1280x800`）首屏不滚动就能看全标题、一句话说明和主按钮；超宽屏锁住版心最大宽度；表格和指标列启用等宽数字。

## 第二步 用只点默认按钮的新手视角过 8 条省心规矩

把自己当成不看说明书、只点眼下最显眼按钮的新手走一遍全流程，按 8 条直接改代码。

1. **程序能自己判断的，别再弹窗问用户。** 自动识别默认路径、格式或系统状态，并在界面明处展示当前选中项，留一个手动改入口。
2. **这一步用不上的选项，先收起来。** 只收低频高级项（自定义端口、实验开关），主按钮与安全提示绝不藏进二级菜单。
3. **能替用户做完的，直接做完。** 自动清理空格、补全协议头、校验格式并给出可读中文说明，不把英文报错码甩给用户。
4. **同一件事在各个页面叫法和位置保持一致。** 术语、按钮文案与放置方向全站统一。
5. **每次点击立刻有回应，做错了能一步撤回。** 按钮按下即反馈状态；删改、批量操作优先给撤销或进回收站。
6. **不弹阻塞式弹窗打断手上的事。** 轻量通知就地展示，不打断输入焦点。
7. **常用操作一步直达，会丢数据的操作多一步确认。** 高频动作不藏三层菜单，高风险动作明确说出删改对象和后果。
8. **不看说明也能读懂每个控件。** 按钮写清动词加对象（如「导出报表」），少用孤立的「确认」「提交」。

## 第三步 按 12 种状态变化查 7 条跟手动效标准

别按组件清单瞎加动画。先把界面里所有状态变化列齐，涵盖**出现、消失、移动、变大小、换内容、换图标、数值跳动、按下、悬停、加载、完成、出错**。逐一按 7 条标准核查。

1. **讲清从哪来、到哪去。** 面板从哪个按钮弹出，关闭时就缩回哪个按钮；进场可从 `0.96` 缩放加透明度起手，禁止从零尺寸在半空凭空蹦出。
2. **全站一套节奏。** 统一使用一套缓动曲线与两三档时长，各组件起落像同一个体系。
3. **快、轻、不抢戏。** 点得越频繁的操作越快越轻；高频快捷键和命令面板不加慢动画拖手。
4. **跟手，半路随时能打断。** 动画播到一半再次操作，必须从当前实时位置平滑折返或衔接，绝不锁死点击，也绝不跳回起点重演。
5. **只动位移、缩放和透明度，不拖慢页面。** 禁止逐帧过渡 `width`、`height`、`top`、`left` 触发反复重排掉帧。
6. **尊重系统「减少动态效果」。** 在 `prefers-reduced-motion: reduce` 下关闭大幅位移与弹跳，换成轻微淡入淡出或色块变化，让人仍能看清状态切了。
7. **宽窄屏和深浅色全部成立。** 桌面宽屏、手机窄屏、浅色模式、深色模式各验一遍，确保文字对比度够、无半字截断。

## 第四步 斜向移鼠防劫持走廊与点击锁定

做悬停展开的二级菜单、侧栏提示卡或悬停详情浮层时，必须解决两个最烦人的手感事故。

1. **斜向移鼠防劫持走廊（安全三角区）。** 当用户把鼠标从触发项斜着移向右侧或下方的展开浮层时，路过相邻触发项极易把当前浮层关掉切换。实现时记录鼠标移动向量，在当前指针坐标与目标浮层上下（或左右）两角之间形成虚拟三角安全走廊；只要指针仍在走廊内朝着浮层移动，短时间宽限内不切换相邻项。
2. **点击锁定。** 悬停打开的预览卡或操作浮层，一旦用户点击触发项或浮层内部，立即进入锁定态，移出鼠标不自动关闭，方便长文阅读、点选按钮或复制文本；再次点击触发项、按 `Esc` 键或点击空白处即解锁关闭。

## 第五步 任意条数据弹性扩容

严禁把当前样例的数量（例如 4 个标签、20 条列表、3 层展架）写死进 CSS 固定像素、正则表达式或硬编码数组下标。

- 数量驱动布局改用 CSS 变量动态等分（如 `--item-count`）、`auto-fit` 网格或超阈值自动切换紧凑态与横向轻滑。
- 筛选区和标签栏加高度保护，条目增多时自动折叠或单行横滑，绝不把正文挤成窄缝。
- 容器高度严禁在缩小了 `font-size` 的同一元素上用 `em` 自引用硬定高，防止多行折行被纵向切边。
- 卡片、列表和抽屉支持从 0 条（清晰空态）、1 条、10 条到 100 条以上自然生长，增删数据只改纯数据文件，不动布局代码。

## 第六步 每改一处都往后多想两步

`rigor.impactCheck` 为 `on`（默认）时，每改一处界面或交互，落盘前写清两句话；为 `off` 时只在改动会删掉入口或改变老用户习惯时写。

1. **二阶影响**，说清这处改动会连带影响哪个相邻页面、哪种屏幕尺寸，或者会不会顺手把老用户常用的入口和排错出口删没了。
2. **三阶影响**，估算三个月后数据量翻倍、再加两个新分类或换新人接手维护时，这套写法会不会变成越改越脆的烂摊子。

确认没有埋新坑，才正式写入文件。
