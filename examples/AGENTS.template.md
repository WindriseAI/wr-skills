# 项目协作总纲（AGENTS.md 模板）

> 把本文件复制到项目根目录改名为 `AGENTS.md`。如果同时使用 Claude Code，在根目录放一个 `CLAUDE.md`，正文只写一行 `@AGENTS.md` 保持单源同步。
>
> 下面是「完整档」写法。小项目或一个人做时，可以只留第 3 节的头两条和安全那一条。具体强度（要不要先写规格、搜几个开源方案、并不并行）以 `wr.config.json` 首次对齐时写下的答案为准，本文件和配置冲突时按配置办。

## 1. 开工前准备（挑刺问清、十倍目标与下三角解耦）

- 新功能或大改动开工前，先用 `wr-ask-first` 查本机可用 Skill 并搜一批现成开源方案（数量按 `rigor.openSourceSurveyCount`，默认 5 个）对比体积与协议；发现泄密风险、上下文膨胀、前后矛盾或二三阶连带隐患，必须当面提出，再通过决策树分轮追问落盘到 `docs/SPEC.md`。
- 用户提到性能或体积时，用 `wr-10x-goal` 交代清楚真实背景与基准指标，定十倍目标（追求十倍速度并用十分之一时间分路跑完、对比十个现成方案、把体积与冗余压小十倍），算出硬盘、内存与网络的物理下限，并死守四条防作弊红线（严禁偷删功能、硬编码假返回值、跳过慢路径或改弱测试断言）。
- 拆开并行派活前，先用 `wr-axiomatic-design` 提取独立功能需求 FR 与设计参数 DP 画出依赖矩阵，通过重排顺序和抽取唯一真源消掉右上角反向耦合，确认呈下三角阵或对角阵后再启动并发。

## 2. 开工、多路并行与实战模型排兵布阵

- **总协调人**，用最强推理档（`modelTiers.tier1_architect`）。收到问题先向人汇报方案与做法，再派对应帮手去做。推荐挂前置钩子防止协调人闷头看代码不回复：本仓库带了「先应声再动手」（`hooks/speak-before-act-hook.mjs`）；限制单轮工具调用次数或时长、拦截协调人直接改业务代码这两类钩子未随包提供，需要时按 `wr-hook-forge` 自己写。
- **总设计师**，界面与设计类的活固定交给同一档模型（通常也是最强推理档），不在中途随意换模型。
- **其余执行、排错与分析任务**，按现有订阅方案由总协调人结合模型特点与不同思考强度拆开派活；只有一个模型时就是单模型模式，不分档。
- **多代理工作台可选**，例如开源的 Orca；没有也能按 `wr-split-work` 的纯 `git worktree` 路线做完。
- 大活（且 `workflow.parallel` 不是 `off`）按 `wr-split-work` 拆给独立会话和独立 `git worktree`，每份任务书锁定独占文件白名单，禁止两条支线同时修改同一文件；超过 300 行的文件先看结构大纲再按段读取；帮手交活固定三句话汇报（做了什么、发现了什么、还剩什么）加本轮真实命令输出。
- 零例外客观硬规矩按 `wr-hook-forge` 写成 `hooks/` 里的静态脚本，同一类低级错误踩到第二次就落进钩子，先挂 `observe` 观察档跑顺再切 `enforce` 硬拦。

## 3. 跑通功能、真路径验收与独立盲审

- 没有本轮刚跑出来的真实命令输出，绝不汇报完成。
- 按 `wr-real-qa` 建立改动文件到行为测试映射，硬禁漏测（`UNMAPPED`）与空跑（`ZERO_RUN`），核心测试用突变探针验真；同一验证连改两次未通过立即停手，列出共同隐藏假设并写最小脚本反证。
- 一整波功能合入集成头后，按 `wr-skeptic-audit` 交给物理隔离的三个全新只读会话（新手查交互、普通读者查文案、资深工程师审 diff）做盲审总验。
- 不触碰凭据与环境变量真文件（仅允许读 `.env.example` 等模板），工作区外不执行永久强删；推送远端、发版与外部网站提交前是否等人确认，按 `workflow.publishConfirm`（默认推送和发版必须等确认）。

## 4. 功能稳后界面打磨

- 核心功能全部跑通验收后，再按 `wr-ux-craft` 统一打磨界面体验。
- 复杂判断留给程序，用户视角按只点默认按钮的新手过一遍，低频项收起，主操作一步直达。
- 动效按状态变化核查，全站一套曲线，只动位移、缩放和透明度，半路可打断，兼容减少动态效果与深浅色；`rigor.impactCheck` 打开时，每处改动前先核查二阶（连带页面和老用户习惯）与三阶（三个月后扩容和维护成本）影响。
