# 项目协作总纲（AGENTS.md 模板）

> 把本文件复制到项目根目录改名为 `AGENTS.md`。如果同时使用 Claude Code，在根目录放一个 `CLAUDE.md`，正文只写一行 `@AGENTS.md` 保持单源同步。

## 1. 定十倍目标、防作弊、挑刺与立据

- 交齐真实背景和基准指标后，定十倍目标（追求十倍速度并用十分之一时间分路跑完、动手前搜齐十个现成方案对比、把体积与冗余压小十倍），并算出硬盘、内存与网络的物理下限。
- 死守四条防作弊红线，严禁靠偷删功能、硬编码假返回值、跳过慢路径（或用假替身顶替核心逻辑）和改弱测试断言来凑指标。
- 新功能或大改动开工前，先查本机可用 Skill 并横向对比现成开源方案，能安全复用轻量方案就不从零造轮子。
- 发现需求里有泄密风险、上下文膨胀、前后矛盾或二三阶连带隐患，必须当面提出，绝不盲从开工。
- 复杂需求通过决策树分轮追问，全部敲定后写入 `docs/SPEC.md` 作为唯一准数再写代码。

## 2. 下三角解耦、分桌并行与上下文卫生

- 拆桌派活前先按公理设计提取独立功能需求 FR 与设计参数 DP 画出依赖矩阵，通过重排顺序和抽取唯一真源消掉右上角反向耦合，确认呈下三角阵或对角阵后再启动并发。
- 大活拆给独立会话和独立 `git worktree`，每份任务书锁定独占文件白名单，禁止两桌同时修改同一文件。
- 超过 300 行的文件先看结构大纲再按段读取，避免整仓硬塞进单轮对话。
- 帮手交活固定三句话汇报（做了什么、发现了什么、还剩什么）加本轮真实命令输出。

## 3. 体验、动效与连带推演

- 复杂判断留给程序，用户视角按只点默认按钮的新手过一遍，低频项收起，主操作一步直达。
- 动效按状态变化核查，全站一套曲线，只动位移、缩放和透明度，半路可打断，兼容减少动态效果与深浅色。
- 每处改动前先核查二阶（连带页面和老用户习惯）与三阶（三个月后扩容和维护成本）影响。

## 4. 验货、真测与根因纪律

- 没有本轮刚跑出来的真实命令输出，绝不汇报完成。
- 改动文件到测试映射禁止漏测（`UNMAPPED`）与空跑（`ZERO_RUN`），核心测试用突变探针验真。
- 同一验证连改两次未通过立即停手，列出共同隐藏假设并写最小脚本反证。
- 一整波功能合入集成头后，统一交给物理隔离的新只读三席会话（交互、文案、diff）做盲审总验。

## 5. 零例外硬规矩交给钩子

- 不触碰凭据与环境变量真文件（仅允许读 `.env.example` 等模板）。
- 工作区外不执行永久强删，清理旧数据优先移入回收站。
- 推送远端、发布上线、外部网站提交前先等人确认（已获明确授权除外）。
- 同一类低级错误踩到第二次，固化成 `hooks/` 里的静态脚本，先挂 `observe` 再切 `enforce`。
