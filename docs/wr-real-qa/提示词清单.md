## 一、建立改动到测试映射，硬禁 `UNMAPPED` 与 `ZERO_RUN`

```text
没有这一轮刚跑出来的命令输出，不许说已经完成或看起来没问题。
请先根据 git diff 列出本次改动的所有核心文件，建立「改动文件 → 对应行为测试」映射表，并按下面三条执行。
1. 任何核心改动文件找不到对应行为测试的，标为 UNMAPPED，先补测试再谈通过。
2. 运行对应测试与静态检查，核对实际执行用例条数；如果筛选写错导致跑了 0 条用例（ZERO_RUN），按失败处理。
3. 完整读完退出码与日志，汇报时只贴关键两三行原始输出，没测到的范围直写没测。
```

## 二、破测试突变探针，清查假绿水测试

```text
逐条排查【目标测试目录】里的测试到底能不能抓住真实缺陷。
1. 标出并重写这五类水测试，分别是读源码搜关键词冒充行为测试、吞掉断言异常或漏写 await、硬睡固定秒数、强行点击绕过界面遮挡、把核心逻辑全换成假替身自己测自己。
2. 对核心业务测试逐一做破测试突变探针，也就是临时把被测业务里的一个关键条件改反（或注释掉写入数据的那一步），重跑对应测试。测试如果不变红，说明这条测试无效，必须重写。
3. 探针完成后立刻把业务源码原样还原，并用 git diff 核实源码没有残留任何探针改动。
4. 保留对外接口契约、权限白名单、加密握手和旧数据迁移测试，不要误删。
```

## 三、浏览器 `getBoundingClientRect` 像素裁切与遮挡扫描

```text
在真实浏览器环境下打开【目标页面地址】，分别切到桌面宽屏（1440x900）、手机窄屏（390x844）、浅色模式和深色模式。
1. 像真用户一样把页面上的每个主要按钮、开关、标签、抽屉和链接点一遍，核对交互反馈是否正常。
2. 在每种视口和主题下注入几何检测脚本，利用 getBoundingClientRect()、scrollWidth/clientWidth、scrollHeight/clientHeight 与 elementFromPoint() 扫描下面三项。
   - 整页横向溢出
   - 容器 overflow 导致的横向或纵向文字截断
   - 可点击控件中心点被伪元素、阴影层或浮层遮挡
3. 把扫出的全部问题按「视口/主题 + 元素文本 + 缺陷类型 + 溢出像素或遮挡层」列成表，修完复测归零后再汇报。
```

## 四、先核实真根因，连败两次立即熔断

```text
我对这个故障原因的猜测可能是错的。动手改代码之前，请先独立复现并找出真正根因。
1. 顺着调用链往回查，查到错误状态第一次产生的地方再修，严禁用空 catch、随手加判空或盲目加延时重试把问题盖住。
2. 如果同一道验证连改两次仍未通过，立刻停手，不要尝试第三版微调。把前两次修改共同依赖的隐藏前提写出来，写一个最小复现脚本去验证相反的前提。
3. 根因修好后顺手搜一遍同目录和上下游，同类写法一起修干净，把复现脚本转成回归测试并清掉临时调试日志。
```

## 五、用户群反馈先只读查日志归批，拍板再改

```text
下面是一批用户反馈和报错截图摘要，【粘贴反馈内容】。
先进入纯只读模式，没有我确认，不重启服务、不改线上数据、不对外承诺排期。
1. 对照对应时间段的日志、版本号和代码核实真实原因。
2. 按真正根因把零散反馈归成几批（线上故障 / 操作卡点 / 用户环境差异 / 新需求）。
3. 交给我一份分批清单，每批附证据摘要、最小修法和连带影响范围，等我统一拍板再改。
```
