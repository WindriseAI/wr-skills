## 一、让总协调人拆活并切死独占文件白名单

```text
你是这次任务的总协调人。你只负责拆任务、查证前置事实、写派活任务书、审帮手回执和最后合并，不许自己下场写业务代码。

本次总目标，【描述要完成的一整波功能，附 docs/SPEC.md 路径】。

请先读完规格文件和相关目录大纲（大文件先看大纲再分段读），然后把这波活拆成可以并行推进的 3 到 5 条独立支线，每条支线的任务书都写清下面五项内容。
1. 目标与验收命令
2. 独立 git worktree 路径与分支名
3. 独占文件白名单（硬要求是任意两条支线的白名单不能出现同一个文件，有重叠就调整拆分方式）
4. 对应的通用难度档位（架构与审美 / 逻辑攻坚 / 独立核查 / 机械跑腿）
5. 给帮手的固定三句话交活格式（做了什么、发现了什么、还剩什么 + 真实命令输出）

拆完先给我看清单，我确认后再同时派出去。
```

## 二、加功能前先做减法砍废包压小体积

```text
给【目标模块或安装包】加新功能或做优化之前，先做减法。
1. 全仓排查这个模块里的死代码、没人读的配置项、只转一手的包装函数，以及体积过大却只用了一两个小函数的第三方依赖。
2. 内部接口改动时，把所有调用方全仓搜出来一次迁完，旧接口直接删掉，不留兼容壳（已对外发布的接口、旧版用户存档和线上协议除外）。
3. 给出压小安装包体积或运行时开销的具体减重清单，朝数量级压缩思考结构调整，不许靠砍掉校验、加密或权限判断来凑数字。
4. 做完汇报代码净增或净减多少行，产物或依赖体积从多少降到多少。
```

## 三、把数据与版式拆开存放消除文件冲突

```text
改造【目标页面或配置模块】，把业务数据、视觉变量和渲染逻辑彻底拆开。
1. 颜色、字号、间距、圆角统一进根级样式变量文件。
2. 列表条目、文案、规则抽成纯数据文件，文件头注明每个字段含义，以后加一条只需往数组末尾追加一个对象。
3. 核心状态改成互斥状态类型，禁止用多个布尔开关拼出非法组合；外部输入在入口一次性解析，失败报出字段名。
4. 改完回答一个问题，以后往这里加一条新内容要改几个文件？正确答案应该是 1 个。
```

## 四、给单个并行帮手的标准开工指令

```text
你是一个独立执行帮手，工作目录在【独立 worktree 路径】，分支为【分支名】。

本次任务目标是【一句话目标】。
参考规格在【docs/SPEC.md 的对应小节】。
独占文件白名单为【逐条列出允许修改的文件】。白名单以外的文件一律禁止修改；如果发现必须改白名单外的文件，立刻停下来向协调人汇报。

完工前必须对真实产物运行【静态检查与测试命令】并读完输出。
交活时只写三句话汇报做了什么、发现了什么、还剩什么，附修改文件列表和关键两三行真实命令输出。
```

## 五、性能多路并发提速十倍（带防作弊底线）

```text
把【目标慢操作，当前耗时 X 秒】朝【目标耗时，例如 0.1 秒】做结构级优化，守住下面四条要求。
1. 先测出当前每一步的真实耗时分布，并算出磁盘、内存或网络的物理理论下限。
2. 优先从结构上提速（消除重复扫描、批量化处理、流式零拷贝、安全并发），别只在慢结构上微调参数。
3. 两条防作弊底线，严禁为了数字好看砍掉签名校验、加密或权限检查；物理下限够不到的如实交出实测数据。
4. 交付前后同环境的基准实测对比输出。
```
