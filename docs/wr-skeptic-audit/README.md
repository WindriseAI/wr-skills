# wr-skeptic-audit

[← 返回 wr-skills](../../README.md) · [English](../../README.en.md#skills)

> 三席物理隔离独立盲审。把合并后的验货拆给三个彼此不见面的全新只读会话，分别由禁读源码的新手用户审交互、禁读源码的老编辑替普通读者把关文案，再由全新只读的资深工程师按八项清单审 diff。

**按 Skills 通用格式编写，可用于 Claude Code、Codex、Cursor、Antigravity、claude.ai 等支持 Skills 的 Agent**（各家没有逐一实测）。 用的 AI 不支持 Skill，也可以直接复制 [提示词清单](提示词清单.md)。

## 为什么必须三席隔离

在同一个对话里让写代码的 AI 顺手检查，它满脑子都是「为了绕过某个坑才这么写」的合理化解释，几乎一定会放过自己埋的雷。让懂代码的工程师去审交互和文案，他又会因为看懂了底层实现而觉得「这按钮挺清楚的呀」。

把三个视角彻底物理隔离，切断源码与辩解的干扰，就能在发版前用极低成本抓出绝大多数低级返工。

## 三席分工对照表

| 席位 | 能不能读源码 | 只给看什么材料 | 专挑哪类毛病 | 交卷硬标准 |
| --- | --- | --- | --- | --- |
| **第一席 · 新手用户审交互** | **严禁读源码** | 真机截图（宽窄屏、深浅色、空态/满载态）、录屏与点击步数 | 看不懂点哪、步骤绕路、半字截断、阴影遮挡、死按钮、出错没退路 | 每条带截图编号与位置，只挑刺不夸奖 |
| **第二席 · 老编辑替普通读者把关文案** | **严禁读源码** | 界面导出的纯文字、按钮标签、弹窗、报错提示与帮助文档 | 先当普通读者圈看不懂的缩写代号和前后叫法不一，再用编辑眼光圈机器味句子和没核实的夸大 | 每条带原句位置、原句、毛病类型和一句能直接替换的平实改法 |
| **第三席 · 资深工程师只读总审** | 只读，禁改文件 | 用户原话 + `docs/SPEC.md` + `git diff` + 宣称输出（禁作者解释） | 越界改动、合并误冲、契约漂移、死调用、水测试、漏 `await`、吞异常、残留泄露 | 8 项逐一标 `PASS / WARN / FAIL` 并附 `file:line` |

## 什么时候跑最省事

不要每改十行就开三席来回拉扯。等一整批并行分支全部合入集成分支后，集中跑完三席一次列全问题，交回执行方一轮改完，再对照阻断项复核放行。

## 安装

只装这一个技能，运行下面这行命令。

```bash
npx -y skills add WindriseAI/wr-skills -g --skill wr-skeptic-audit
```

一键安装全套风起技能，运行下面这行命令。

```bash
npx -y skills add WindriseAI/wr-skills -g --all
```

更多安装方式见 [主说明文档](../../README.md#安装)。
